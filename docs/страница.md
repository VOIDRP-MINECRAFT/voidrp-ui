# Страница: состояние и события

Страница — это класс, который отвечает на один вопрос: **как я выгляжу прямо сейчас**.
Всё остальное — дело движка.

```kotlin
class ShopPage : Page() {

    private var tab = "оружие"
    private var scroll = 0

    override fun view(): View = screen(style = Theme.scrim, align = Align.CENTER, children = listOf(
        Panel(style = Theme.card, children = listOf(
            tabs(),
            Scroll(children = items(), offset = scroll, id = "list"),
        )),
    ))

    override fun onClick(id: String, button: Button) {
        if (id.startsWith("tab:")) { tab = id.removePrefix("tab:"); refresh() }
    }

    override fun onScroll(direction: Int) { scroll += direction * 40; refresh() }
}
```

Состояние хранит сама страница — обычными полями. Поменяли поле → позвали `refresh()` →
движок собрал описание заново и отправил. Отдельного «обновить вот этот элемент» нет, и это
намеренно: рассинхрона между тем, что на экране, и тем, что в данных, не бывает.

## Что можно спросить у страницы

| | |
|---|---|
| `player` | игрок, которому открыта страница |
| `viewport` | холст этого игрока: `width`, `height`, `size`, `by(...)` |
| `hovered` | `id` области под курсором или `null` |
| `cursorX` / `cursorY` | курсор в единицах холста |
| `region(id)` | где оказалась названная панель после раскладки |

## События

```kotlin
override fun onClick(id: String, button: Button)        // ЛКМ / ПКМ по панели с id
override fun onDrag(id: String, x: Int, y: Int)         // кнопку держат и водят — ползунок
override fun onScroll(direction: Int)                   // колесо: 1 вниз, −1 вверх
override fun onKey(key: Int)                            // слот хотбара 1…9, если usesKeys = true
override fun onClose()                                  // страницу закрыли, чем бы это ни было
```

Ничего из этого не требует мода на клиенте: замах руки — это левый клик, использование —
правый, колесо — смена слота, Shift — «назад». Пока страница открыта, эти действия
проглатываются, так что игрок не ломает блок, тыкая в кнопку.

`onKey` приходит только страницам с `usesKeys = true`, потому что игра шлёт один и тот же
пакет и для цифры, и для колеса. Цифры хороши для вкладок и режимов: хотбар реально
переключается, игрок видит выбранный слот.

## Переходы

```kotlin
push(MarketPage())   // открыть поверх; Shift или back() вернёт сюда
back()               // назад, если есть куда
close()              // закрыть совсем
```

## Ввод текста

```kotlin
prompt(title = "Цена", label = "Сколько просим?", initial = "100") { answer ->
    price = answer.toIntOrNull() ?: price
    refresh()
}
```

Открывается родное игровое поле ввода (страница остаётся на экране), ответ приходит в
колбэк. Это читается как поле на странице, а не как поход в чат.

## Подсказка у курсора

```kotlin
override fun tooltip(): View? = when (hovered) {
    "item:diamond" -> tooltipPanel("Алмаз", listOf("Цена: 120 ₽", "В наличии: 12"))
    else -> null
}
```

Подсказка едет на полосе самого курсора, которая и так отправляется каждый кадр, — поэтому
она следует за мышью, а страница при этом не перерисовывается.

## Наведение без перерисовки

Подсветка того, на чём стоит курсор, по умолчанию рисуется движком на полосе курсора:
страница остаётся как есть. Так и задумано — страница едет целиком (у главной это ~94 КБ),
и перерисовывать её на каждом пересечении карточки означало бы спотыкающийся курсор.

Если странице действительно нужно менять **содержимое** при наведении (а не только
подсветку), включите `input.redraw-on-hover: true` в конфиге — тогда `hovered` меняет и
саму вёрстку.

## Фон до краёв экрана

```kotlin
override val bleed = listOf(Paint(0x000000, 0.97), pageTint)
```

Заливки, которые обязаны доставать до краёв окна, даже если форма экрана угадана неточно.
Движок красит их первыми и шире холста. Туда выносят только цвет — ни текста, ни кнопок.
Зачем это нужно — в [адаптивность.md](адаптивность.md).

## Открыть страницу из своего плагина

```kotlin
val ui = VoidRpUi.get() ?: return          // плагин не установлен
ui.open(player, MyPage())
ui.isOpen(player); ui.current(player); ui.close(player)
```

`open` вернёт `false`, если у игрока нет пака: игроку уже сказали об этом и выслали пак
заново. Если игрок ещё ни разу не настраивал экран, перед его страницей движок сам покажет
настройку формата и после «Готово» откроет то, что просили.
